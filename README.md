# Proximi.io iOS map — binary distribution

This repository is the **public, customer-facing** distribution of the Proximi.io
iOS map package. It contains only a `Package.swift` that pins a precompiled
`ProximiioMapBinary.xcframework` by URL and checksum, a one-line source shim, and
the licence texts. The xcframework itself is attached to each GitHub Release as
an asset. The source lives in a private repository and is not published here.

Every file in this repository is generated by
`scripts/publish-binary-release.sh` in that private repository. Do not hand-edit
anything here: the next release overwrites it.

## Adding it to an app

```swift
// Package.swift
dependencies: [
    .package(url: "https://github.com/proximiio/proximiio-map-ios-binary", exact: "<version>"),
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "ProximiioMap", package: "proximiio-map-ios-binary"),
    ]),
]
```

```swift
import ProximiioMap
```

In Xcode: **File → Add Package Dependencies…**, paste the repository URL, and
pick the exact version.

## What comes with it

Adding this one package brings three things into your build:

| | |
|---|---|
| `ProximiioMap` | this package — the canvas, the renderers, the SDK binding and the SwiftUI face, as one precompiled module |
| `Proximiio` | the Proximi.io positioning SDK, from its own public binary distribution, at the **exact** version this map release was compiled against |
| `MapLibre` | the renderer, at the **exact** version in the support window below |

You do **not** add the SDK separately for the map to work. If your app also uses
the SDK directly, declare it — but it must resolve to the same version this
release pins, which is why that version is `exact:` and not a range.

## One product, not three

The source package vends `ProximiioMap`, `ProximiioMapKit` and
`ProximiioMapCore`. This one vends only `ProximiioMap`.

`ProximiioMapKit` and `ProximiioMapCore` exist in source for one
customer-visible reason: what they keep out of the link graph — the canvas
without the positioning stack, the value types without MapLibre or UIKit. A
binary distribution cannot keep that promise. This artefact is a single
flattened module, so a `ProximiioMapKit` product here would be an alias for the
same bytes; and the promise is already gone one level down, because the map's
Core depends on the SDK's `ProximiioCore`, which in the binary SDK is itself an
alias for the whole flattened SDK.

Vending the names anyway would mean shipping a boundary that does not exist. If
you need the real split — renderers with no positioning stack linked — you want
the source package, and that is a commercial conversation, not a manifest
change.

## MapLibre

**This package is the only place MapLibre is declared.** It is pinned `exact:`,
and it must appear exactly once in your dependency graph.

`MapLibre` is a SwiftPM `binaryTarget`, and SwiftPM cannot deduplicate two
binary targets vending the same product name. A graph that reaches MapLibre
twice at two different versions is a **hard resolution failure**, not a warning.

**If your app already links MapLibre, match our pin.** There is no compatibility
range, because there cannot be one. One MapLibre version per `ProximiioMap` tag;
the version is in this release's `Package.swift` and in the support-window table
in the release notes. An old pin is supported by the tag that carries it and by
nothing else — there is no maintenance branch on an older MapLibre.

## Which SDK does this release want

Each `ProximiioMap` release is compiled against one exact
`proximiio-sdk-ios-binary` release and pins it. The pairing is in this release's
`Package.swift` and in the release notes. Mixing a `ProximiioMap` tag with a
different SDK version is not supported and will not resolve.

## Licence

`LICENSE` covers the Proximi.io map binary. `ThirdParty-MapLibre-LICENSE.txt`
and `NOTICES.md` cover the third-party components you receive with it; both must
travel with any app that ships this package.
